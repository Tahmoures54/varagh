# سامانه کنترل حمل ورق فولادی فراسکو (Varagh)

سامانه تحت وب فارسی برای ثبت حواله‌های حمل، ثبت ورود و خروج کامیون، اطلاعات باسکول، نگهداری فایل قبض‌ها، پیگیری مغایرت و گزارش‌گیری.

## وضعیت فعلی

- برنامه اصلی Flask در فایل app.py قرار دارد.
- پایگاه داده پیش‌فرض SQLite در پوشه data/ ایجاد می‌شود.
- شماره حواله در صورت خالی بودن فیلد، به شکل HV-{سال شمسی}-{XXXX} تولید می‌شود.
- فایل‌های قبض فقط با پسوند PDF/PNG/JPG/JPEG/WEBP و حداکثر ۸ مگابایت پذیرفته می‌شوند و با نام تصادفی ذخیره می‌شوند.
- همه صفحات عملیاتی نیازمند ورود هستند؛ عملیات حذف و مدیریت کاربران فقط برای مدیر مجاز است.
- مدیر می‌تواند حساب‌های کاربری و نقش‌ها را از صفحه «کاربران» ایجاد و فعال/غیرفعال کند؛ رمز اولیه هر حساب باید حداقل ۱۲ نویسه باشد.
- حراست، انبار و پروژه محدودیت‌های جداگانه‌ای برای فیلدهای ورود/خروج، باسکول و تأیید نهایی دارند؛ تکمیل نهایی فقط برای مدیر یا پروژه مجاز است.
- تکمیل حواله نیازمند کد کالای موجودی و وزن خالص باسکول است. کسر موجودی در تراکنش پایگاه داده انجام می‌شود و موجودی ناکافی یا کد نامعتبر مانع تکمیل است.
- حواله‌ای که از موجودی آن کسر شده حذف یا از نظر وضعیت/کد/وزن اسنادی تغییر داده نمی‌شود.
- خروجی Excel برای حواله‌ها در دسترس است.
- مدیر می‌تواند موجودی را از CSV/XLSX وارد کند؛ ورود حداکثر ۵۰۰۰ ردیف و تطبیق تکرارپذیر بر اساس کد کالا، مشخصات و موقعیت دارد. الگوی CSV از صفحه موجودی دریافت می‌شود.
- اگر یک کد کالا چند ردیف موجودی داشته باشد، کسر موجودی فقط با مشخصات یکتای منطبق انجام می‌شود؛ سامانه موجودی یک ردیف دلخواه را انتخاب نمی‌کند.
- رخدادهای مهم در جدول audit_log ثبت می‌شوند.

> این نسخه یک مبنای اجرایی و قابل آزمون است؛ پیش از استفاده عملیاتی، گردش‌کار، داده‌های موجودی، پشتیبان‌گیری و دسترسی کاربران باید در محیط واقعی آزمایش شوند. PDF سه‌نسخه‌ای و گزارش روزانه PDF در این نسخه پیاده‌سازی نشده‌اند و نباید به‌عنوان قابلیت آماده فرض شوند.

## نیازمندی‌ها

- Python 3.11 یا جدیدتر
- pip

## نصب و اجرای محلی

Linux/macOS:

    git clone https://github.com/Tahmoures54/varagh.git
    cd varagh
    python -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    export VARAGH_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
    export VARAGH_ADMIN_PASSWORD="یک-رمز-طولانی-حداقل-۱۲-کاراکتر"
    python app.py

Windows PowerShell:

    git clone https://github.com/Tahmoures54/varagh.git
    cd varagh
    py -m venv .venv
    .venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    $env:VARAGH_SECRET_KEY = (py -c "import secrets; print(secrets.token_hex(32))")
    $env:VARAGH_ADMIN_PASSWORD = "یک-رمز-طولانی-حداقل-۱۲-کاراکتر"
    py app.py

سپس به http://127.0.0.1:5000 بروید و با نام کاربری admin و همان رمز تعیین‌شده در VARAGH_ADMIN_PASSWORD وارد شوید. اگر پایگاه داده از قبل کاربر داشته باشد، این متغیر رمز کاربر موجود را بازنویسی نمی‌کند.

## متغیرهای محیطی

| متغیر | کاربرد |
|---|---|
| VARAGH_SECRET_KEY | کلید محرمانه نشست؛ در استقرار ثابت و تصادفی تنظیم شود |
| VARAGH_ADMIN_PASSWORD | رمز اولیه مدیر؛ حداقل ۱۲ نویسه، فقط برای ایجاد نخستین کاربر |
| VARAGH_ADMIN_USERNAME | نام کاربری مدیر اولیه؛ پیش‌فرض admin |
| VARAGH_DATA_DIR | پوشه پایگاه داده؛ پیش‌فرض ./data |
| VARAGH_UPLOAD_DIR | محل فایل قبض‌ها؛ پیش‌فرض ./data/receipts |
| DATABASE_URL | نشانی پایگاه داده در صورت نیاز به تنظیم سفارشی |
| HOST / PORT | میزبان و درگاه اجرای محلی؛ پیش‌فرض 127.0.0.1:5000 |
| COOKIE_SECURE | برای HTTPS مقدار 1 قرار دهید تا کوکی فقط روی HTTPS ارسال شود |

برای استقرار اینترنتی، VARAGH_SECRET_KEY و VARAGH_ADMIN_PASSWORD را از بخش Environment/Secrets میزبان تنظیم کنید؛ مقادیر محرمانه را در مخزن Git قرار ندهید. پشت پراکسی HTTPS، COOKIE_SECURE=1 را فعال کنید.

## نکات عملیاتی و پشتیبان‌گیری

- از پایگاه داده و پوشه فایل‌های قبض به‌صورت هماهنگ نسخه پشتیبان بگیرید.
- در استقرارهای چندنمونه‌ای یا پرترافیک، SQLite و فایل محلی برای نوشتن مشترک مناسب نیستند؛ از پایگاه داده و فضای فایل پایدار/مشترک مناسب استفاده کنید.
- حساب‌ها و نقش‌ها را پس از ایجاد مدیر، از مسیر مدیریت امن پایگاه داده/فرایند عملیاتی سازمانی ایجاد کنید. رمز پیش‌فرض عمومی وجود ندارد.
- قبل از کسر موجودی، کد کالا و وزن واقعی را کنترل کنید. مقادیر اولیه موجودی باید از داده معتبر وارد شوند.
- فایل قبض‌ها برای کاربران واردشده قابل مشاهده است؛ از قراردادن فایل‌های محرمانه در فضای عمومی خودداری کنید.
